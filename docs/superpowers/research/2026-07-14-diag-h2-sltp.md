  (`run_live_20.audit.log:2922`).

Therefore the session window `01:06:02 → 07:57:05` is **broker-server time** (= audit-log clock), equal to
true UTC 05:06:02 → 11:57:05. All MT5 history was pulled with the window expressed in server time
(`datetime(2026,7,14,1,3,0, tzinfo=timezone.utc)` → `datetime(2026,7,14,7,57,6, tzinfo=timezone.utc)`),
because the MetaTrader5 Python API interprets history datetimes as server time on the UTC epoch.
All timestamps below are broker-server time unless marked otherwise.

## PART A — code facts

### A1. `sentinel_engine/live/reconciler.py` — action kinds and conditions

Declared kinds (reconciler.py:52–54): `OPEN | CLOSE | MODIFY | NOOP | REJECT_VOLUME | REJECT_CAP |
SUPPRESSED_OPEN | SAME_BAR_EXIT_FALLBACK | MISSING_SL_ALARM`.

Emission conditions, in reconcile order (reconciler.py:114–280):

| kind | condition (file:line) |
|---|---|
| `CLOSE` (duplicate) | two live positions share one ficha slot (164–167) |
| `SAME_BAR_EXIT_FALLBACK` | live position exists, ficha absent from sim `open` state, AND present in `last_bar_exits` (sim exited within the just-closed bar) (183–200) |
| `CLOSE` (orphan) | live position exists, ficha absent from sim state, not in `last_bar_exits` (201–205) |
| `CLOSE` (side mismatch) | live side ≠ sim side for the slot (214–221) |
| `MISSING_SL_ALARM` | desired ficha open live but live SL is `None`/0.0 (228–233) |
| `MODIFY` | `desired_sl is not None and (live_sl is None or live_sl==0.0 or abs(live_sl - desired_sl) > sl_tol)` with `sl_tol=0.05` (234–241) |
| `NOOP` | desired ficha open live, SL within tolerance (243–246) |
| `REJECT_VOLUME` | OPEN wanted but `volume > MAX_VOLUME` (0.10) (254–259) |
| `REJECT_CAP` | OPEN wanted but `running_total >= MAX_FICHAS_TOTAL` (60) (261–267) |
| `SUPPRESSED_OPEN` | OPEN wanted but `kill_switch` True (268–273) |
| `OPEN` | sim ficha open, no live position, all caps pass (274–278) |

**No action kind carries a take-profit level.** The `Action` dataclass (50–65) has fields
`kind, config_id, magic, ficha, side, volume, price_ref, sl, ticket, sim_fill, motivo, reason` —
there is no `tp` field anywhere in the module (0 grep hits for `tp` as a field).

**Desired SL for MODIFY** comes directly from the sim state: `d = open_state[tag]` (reconciler.py:210),
`desired_sl = d.get("sl")` (223), where `open_state` is `simular_variant(..., return_state=True)`'s
`{"F1"|"F2"|"F3": {"side","entry","sl", ...}}` snapshot (docstring 132–134). Emitted as
`Action("MODIFY", ..., sl=desired_sl, ...)` (237–241).

### A3. `sentinel_engine/strategies/emasar_variant.py` — EXIT_TP reachability

`simular_variant` signature: `f1_tp_r: float = 0.0` (line 111), `f2_tp_r: float = 0.0` (line 112);
`tp_by_tag = {"F1": f1_tp_r, "F2": f2_tp_r}` (386). EXIT_TP fires only inside `if tp_r > 0.0:`
(423), long at `bar["high"] >= entry + tp_r*R` (432–437), short at `bar["low"] <= entry − tp_r*R`
(438–444). F3 never TPs (docstring 164).

`live_configs_20.CONFIGS_20`: **zero of the 20 configs pass `f1_tp_r` or `f2_tp_r`** — grep for `tp_r`
over `sentinel_engine/strategies/live_configs_20.py` returns no matches; all 20 therefore use the 0.0
defaults. **No live config can ever emit EXIT_TP.**

### A4. Sim SL trigger tests, verbatim

- Initial-SL check (emasar_variant.py:452, 457): long `if f.lado == +1 and bar["low"] <= sl_check:`;
  short `if f.lado == -1 and bar["high"] >= sl_check:` — exit price = `sl_check`.
- Same tests at 425–426 (pre-TP gate) and in the trailing sections at 523 (`if bar["low"] <= sl_check:`)
  and 551 (`if bar["high"] >= sl_check:`).

The bars the sim consumes (lake parquet and live `copy_rates_from_pos`) are MT5 OHLC bars, which are
**BID-based**. Flagged as MT5-documentation knowledge (not measured here): a broker executes a long SL
when **BID ≤ SL** and a short SL when **ASK ≥ SL**. (So the long-side sim test `low ≤ sl` matches broker
semantics on the same price stream; the short-side sim test uses bid `high` while the broker triggers on
ask.)
