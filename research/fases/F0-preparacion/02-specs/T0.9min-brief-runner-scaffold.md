## Qué hay que construir (spec cerrado)

Un paquete Python en **`scripts/research/runner/`** con estos módulos:

### 1. `manifest.py` — carga y validación del manifiesto
- Carga un manifiesto **YAML** (pyyaml 6.0.2 está instalado y verificado).
- Campos obligatorios de nivel raíz: `experimento`, `area`, `etapa`, `hipotesis`,
  `substrate_id`, `engine_sha`, `salidas.resultados`, `salidas.ledger`, y `corridas`
  (lista no vacía).
- Cada elemento de `corridas` lleva `run_key` (string, **único** dentro del manifiesto) y
  `tipo` (string, nombre del task-type registrado). El resto de claves se pasan como parámetros
  a la tarea.
- **Fail-loud:** campo obligatorio ausente, `run_key` duplicado, `corridas` vacío, o `tipo` no
  registrado ⇒ excepción con mensaje que nombra el campo exacto. **Jamás** rellenar con un valor
  por defecto.
- Ejemplo de manifiesto en `research/protocolos/06-runners.md` — respétalo.

### 2. `lineage.py` — tags obligatorios
- Función que construye el dict de tags del protocolo 04 parte 3:
  `run_id, area, experimento, config_hash, substrate_id, engine_sha, git_sha, etapa, generador,
  timestamp`.
- `git_sha`: leído de `git rev-parse --short HEAD`. Si git falla ⇒ fail-loud.
- `config_hash`: `sha256` (hex, truncado a 16) del dict de parámetros de la corrida, serializado
  con claves ordenadas.
- `timestamp`: hora **local del host** en ISO 8601 sin zona.
  🔴 **El host está en UTC−4, que ES la hora de servidor del bróker. PROHIBIDA toda conversión
  de zona horaria.** No uses `utcnow()`, no apliques offsets.

### 3. `ledger.py` — escritor append-only
- Una función que recibe un dict y añade **una línea JSON** a `research/LEDGER.jsonl`.
- **Valida los 13 campos obligatorios** de `LEDGER.schema.md` ANTES de escribir; si falta uno,
  falla y **no escribe nada**.
- Abre siempre en modo **append**. 🔴 **Jamás** leer-modificar-reescribir el fichero, jamás editar
  ni borrar una línea existente. Encoding utf-8 explícito.
- Debe soportar el campo opcional `supersedes` + `reason`.

### 4. `state.py` — reanudación
- Fichero de estado por experimento (JSON) que registra qué `run_key` ya completaron.
- Ubicación: junto a `salidas.resultados`, con nombre `_runner_state.json`.
- API mínima: cargar, consultar si un `run_key` está completo, marcar completo (persistiendo
  inmediatamente, para que un corte no pierda el progreso).

### 5. `tasks.py` — registro de tipos de tarea
- Un registro `nombre -> callable`. El callable recibe `(params: dict, out_dir: Path)` y devuelve
  un dict de métricas.
- Incluye **un único** tipo de referencia, `echo`, que escribe sus params a un fichero en
  `out_dir` y devuelve `{"bytes": N}`. Existe para los tests; no es funcionalidad de producto.

### 6. `runner.py` — orquestador + CLI
- CLI: `python -m scripts.research.runner.runner <ruta-al-manifiesto>` (o el patrón de invocación
  que ya usen los scripts del repo — ver "Cuidados").
- Flujo: validar manifiesto → para cada corrida **no completada** → ejecutar el task-type →
  escribir artefactos en `salidas.resultados/<run_key>/` → marcar completa en el estado →
  **append** de una fila al LEDGER si `salidas.ledger == "append"`.
- Al terminar: escribir un **registro consolidado** en
  `salidas.resultados/_resumen.json` con una entrada por corrida (run_key, estado, métricas,
  ruta de artefactos). Es lo único que el LLM leerá después.
- **Fail-loud:** si una corrida lanza una excepción, **aborta la ejecución completa**, deja el
  estado consistente y sale con código ≠ 0. 🔴 Jamás continuar en silencio ni rellenar con
  defaults.
- **Sin decisiones:** el runner ejecuta lo que dice el manifiesto. No elige, no poda, no ajusta.

## Tests obligatorios (los cinco, con TDD)

1. **Idempotencia:** ejecutar el mismo manifiesto dos veces no duplica filas del LEDGER ni
   re-ejecuta corridas ya completas.
2. **Reanudación:** con un estado que marca la mitad de las corridas como completas, solo se
   ejecutan las restantes.
3. **Fail-loud de manifiesto:** un manifiesto al que le falta un campo obligatorio aborta con
   error que nombra el campo, y **no escribe ninguna fila** en el LEDGER.
4. **Fail-loud de corrida:** si una tarea lanza excepción, el runner aborta con exit ≠ 0 y las
   corridas posteriores **no** se ejecutan.
5. **Lineage completo:** la fila escrita en el LEDGER contiene los 13 campos obligatorios, con
   `git_sha` real y `timestamp` sin conversión de zona.

🔴 Los tests escriben en un LEDGER **temporal** (`tmp_path`), **nunca** en
`research/LEDGER.jsonl`. Ese fichero es del controlador y es append-only real.
