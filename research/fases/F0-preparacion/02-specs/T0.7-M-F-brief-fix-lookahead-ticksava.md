## What just happened, and why this task exists

Task **T0.7-M-E** (commits `f3dda1a`, `9a0eb04`, `404a125`) fixed an unbounded forward tick search in
`bt.Ticks.first_at` (`scripts/analysis/realtick_bt/backtest.py`). In a market gap it returned a tick
from far in the future and the engine used it as the price prevailing at the requested instant —
look-ahead. Measured on the genuine calls of the long AVA backtest: **945 of 13,672 calls (6.9 %)**
returned a price more than 60 s in the future, up to **21 hours**. After the fix: **0**, and the
long-backtest position counts dropped by 2-3 % (S6 4,578→4,482 · S7 5,364→5,253 ·
SuperTrend 1,617→1,566) — those were positions that only existed because of the future price.

The fix added a keyword-with-default tolerance:
`Ticks.__init__(*, tolerance_s: float = 60.0)`, and `first_at` now returns `None` when
`t_tick - t_sec > tolerance_s`. Read commit **`f3dda1a`** — **it is your template**.

**Everything that instantiates `bt.Ticks` inherited that fix for free**, verified by reading:
`capa1_senal_cruda.py:389`, `capa3_gate_spread.py:413`, `exp_active_fichas.py:195` and
`signal_level.py:298` all call `Ticks()` and now get the bounded behaviour by default.

## The one place the fix did NOT reach

`scripts/analysis/a6_pata_a/signal_level.py:73` declares **`class TicksAva:`** — a **standalone
class, NOT a subclass of `bt.Ticks`** — carrying its own verbatim copy of the defect at
`signal_level.py:125-133`:

```python
    def first_at(self, t_sec: float):
        for ym in self._candidates(t_sec):
            ta, bid, ask = self._load(ym)
            if not len(ta):
                continue
            i = int(np.searchsorted(ta, t_sec, "left"))
            if i < len(ta):
                return float(ta[i]), float(bid[i]), float(ask[i])
        return None
```

Identical shape, identical defect, zero inheritance from the fixed class.

### 🔴 Why this is not cosmetic — the asymmetry is the real problem

`signal_level.py:298-299` instantiates **both**:

```python
    cap_ticks = Ticks()        # Capitaria -- NOW BOUNDED (fixed by T0.7-M-E)
    ava_ticks = TicksAva()     # AVA       -- STILL UNBOUNDED
```

That module exists to compare the **Capitaria feed against the AVA feed** (A6 Pata B, feed transfer,
plan §4.2). As of commit `f3dda1a` the two sides of that comparison **no longer share the same
look-ahead behaviour**: one side is bounded, the other is not. Any divergence the module reports
would mix a genuine feed difference with an artefact of the fix, and would be attributed to the
feed. Leaving this asymmetry in place is worse than the original defect, because it is invisible.

## What to build (closed spec)

### F.1 · Bound `TicksAva.first_at`

Apply the **same** correction as `f3dda1a`, with the **same semantics and the same default**:

- Add a keyword argument with a default to `TicksAva.__init__`: `tolerance_s: float = 60.0`
  (keyword-only, mirroring `Ticks`). Store it as an instance attribute.
- In `first_at`, if the found tick satisfies `t_tick - t_sec > self.tolerance_s`, return **`None`**
  instead of the tick.
- The default is **ON**. Do not make it opt-in. A fix you have to remember to enable silently
  reintroduces the defect the first time someone forgets — charter §A.13 calls that silent
  degradation.
- `60.0` is not eyeballed: on the measured distribution the p90 of healthy calls is 3.268 s and every
  contaminated call was above 60 s. Use the same number so both feeds are treated identically —
  **that identity is the whole point of this task.**

🔴 **Do NOT refactor `TicksAva` to subclass `bt.Ticks`.** It is tempting and it is out of scope: its
`_load` differs and the change would alter behaviour beyond the bound. Copy the bound, not the
architecture. If you believe the refactor is necessary: **STOP and escalate.**
