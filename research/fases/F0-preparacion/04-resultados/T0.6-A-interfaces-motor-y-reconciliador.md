### 3 · ¿Permite el flujo de eventos reconstruir el SL vigente por cada barra cerrada?

**No directamente.** Evidencia de código:

- El SL vigente de cada ficha vive en el atributo `f.sl` del objeto `_Ficha`
  (`sentinel_engine/strategies/emasar_ref.py:254-264`, `__slots__ = ("lado", "entry", "sl",
  "max_fav", "abierta", "es_runner", "stall_consec")`), importado en
  `emasar_variant.py:39`. Es un **valor mutable in-place**, sobrescrito bar a bar
  (`emasar_variant.py:989-990` rama larga, `:1027-1028` rama corta) — no hay ninguna lista ni
  histórico que acumule sus valores sucesivos.
- Solo hay **eventos** en `ENTRY_*` y `EXIT_*`. No existe ningún evento tipo `"MODIFY"` o
  `"TRAIL_UPDATE"` que se emita cuando el trailing mueve el stop sin cerrar la ficha. El único
  rastro del SL vigente en el evento stream es el `precio` de un evento `EXIT_*`, que es el nivel
  de SL **en el instante en que se cruzó** — inexistente para las barras intermedias en las que
  la ficha siguió abierta.
- El único mecanismo que expone el SL de una ficha abierta es `return_state=True`
  (`emasar_variant.py:1441-1479`), y **solo para la última barra procesada** de la lista `bars`
  pasada — no para cada barra cerrada de una corrida completa. Para obtener el SL vigente en la
  barra `i` de una corrida de `n` barras, hay que invocar `simular_variant(bars[:i+1],
  return_state=True, ...)` como llamada independiente (recorrer todo el histórico desde 0 hasta
  `i` en cada invocación) — es exactamente el patrón que usa el reconciliador vivo cada ciclo
  (ver Bloque 2, pregunta 6).
- Variable interna donde vive el dato que falta: `f.sl` (atributo del objeto `_Ficha`, definido
  en `emasar_ref.py:260`, actualizado en `emasar_variant.py:989-990`/`:1027-1028`), sin
  persistencia entre iteraciones del bucle salvo el propio objeto en memoria.

Dentro de `run_cycle` (`b113eb7:813-891`), por ciclo:
1. `guard_cuenta.assert_demo(mt5)` (`:834`) — re-verifica la cuenta ANTES de cualquier orden.
2. Lee el kill-switch (`STOP_FILE.exists()`, `:835`).
3. Si hay `spread_store` (adaptativo — **no es el caso** con `--no-adaptive-spread`), registra el
   spread actual por símbolo y deriva `spread_threshold_by_symbol` (`:845-858`).
4. Para cada config del roster (`:861-882`), llama `reconcile_config(...)` (`:862-864`).
5. Para cada acción devuelta, llama `execute_action(...)` (`:871-878`).
6. Acumula `total_open` (fichas deseadas `OPEN`+`NOOP`) para el cap global de 60 (`:882`).

`reconcile_config` (`b113eb7:333-427`), por config:
1. Determina el símbolo y si el motor es intrabar (`:338-343`).
2. `fetch_bars(mt5, symbol, cfg["tf"], window, include_forming=intrabar)` (`:344`) —
   `copy_rates_from_pos(symbol, timeframe, 0, window+1)` (`:293`), **excluye la barra en
   formación** por defecto (`:299-300`, "close-driven").
3. Rama por `engine`: para S6-K2P0 (sin `engine` en su config, motor por defecto)
   `_events, desired = simular_variant(bars, return_state=True, **kwargs)` (`:387`); para
   SuperTrend (`engine == "supertrend_always_in"`) `desired =
   supertrend_always_in_target(bars)` (`:357`).
4. `live = fetch_live_positions(mt5, cfg["magic"])` (`:389`) — posiciones MT5 filtradas por la
   banda de magics de esta config (`:303-319`).
5. `res = reconcile(cfg["id"], cfg["magic"], desired, live, volume=cfg_volume,
   max_volume=cfg_max_volume, bar_t=bars[-1]["t"], kill_switch=kill_switch,
   total_open_fichas=total_open_fichas)` (`:407-410`).
6. Devuelve `(res, bars[-1]["t"])` (`:427`).

Cada ciclo, cada config, **re-simula desde cero** sobre las últimas `window` barras — no hay
estado incremental entre ciclos del lado del sim; el estado deseado se recalcula íntegro cada vez
(consistente con la pregunta 3-4 del Bloque 1: no hay estado persistido salvo re-simular).

### 9 · Fórmulas literales — `OPEN_SKIPPED_SL_CROSSED`, `SL_CLAMPED`, `FALLBACK_CLOSE_INVALID_SL`

Las tres derivan de `_clamp_sl` (`b113eb7:run_live_20.py:467-491`):
```python
def _clamp_sl(mt5, symbol, side, desired_sl):
    tick = mt5.symbol_info_tick(symbol)
    level = _stops_level_points(mt5, symbol)
    if side == "L":
        ref = tick.bid
        if desired_sl >= ref:
            return "crossed", ref
        if desired_sl > ref - level:
            return "clamp", ref - level
        return "legal", desired_sl
    else:
        ref = tick.ask
        if desired_sl <= ref:
            return "crossed", ref
        if desired_sl < ref + level:
            return "clamp", ref + level
        return "legal", desired_sl
```
donde `level = _stops_level_points(mt5, symbol)` (`:437-447`):
```python
def _stops_level_points(mt5, symbol):
    info = mt5.symbol_info(symbol)
    if info is None:
        return 0.0
    stops = float(getattr(info, "trade_stops_level", 0) or 0)
    freeze = float(getattr(info, "trade_freeze_level", 0) or 0)
    point = float(getattr(info, "point", 0.0) or 0.0)
    return max(stops, freeze) * point
```

- **`OPEN_SKIPPED_SL_CROSSED`** (condición exacta): `mode == "crossed"` en una acción `OPEN`
  (`:772-776`) — long: `desired_sl >= tick.bid`; short: `desired_sl <= tick.ask`.
- **`SL_CLAMPED` / `SL_CLAMPED OPEN`**: `mode == "clamp"` — long, no cruzado y `desired_sl >
  tick.bid - level`; short, no cruzado y `desired_sl < tick.ask + level`. Nivel enviado:
  `ref - level` (long) / `ref + level` (short).
- **`FALLBACK_CLOSE_INVALID_SL`**: `mode == "crossed"` pero en una acción `MODIFY`
  (`:719-745`) — misma fórmula "crossed" de arriba, aplicada a una posición YA abierta en vez de
  a una apertura nueva; en vez de enviar un `MODIFY` inválido, cierra a mercado.
